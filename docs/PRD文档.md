# 语音日历 AI Native PRD 文档

## 1. 产品概述

语音日历 AI Native 是一个以语音和自然语言为主要入口的日历管理 Web App。用户可以通过语音或文本添加、删除、查看、调整日程和提醒。系统不仅提供传统日历视图，还提供 AI Agent、工具调用、确认卡片、撤销、日志时间线和企业协作视图，体现 AI Native 产品形态。

第一版交付目标是完成“个人 AI 日程伴侣 + 企业协作日历工作台”的可演示闭环。

## 2. 背景与目标

### 2.1 用户痛点

- 手动创建日程步骤多，尤其是在移动或开会场景中不方便。
- 中文自然语言时间表达复杂，传统表单输入效率低。
- 删除、批量调整、多人会议改期容易误操作。
- 企业协作日程需要按项目、负责人、状态、优先级等维度查看。
- AI 执行操作如果不可解释，会降低用户信任。

### 2.2 产品目标

- 让用户通过语音完成日程添加、查看、删除、提醒和改期。
- 让 AI 成为主要操作入口，而不是附加聊天框。
- 通过受控工具调用、权限校验、风险确认和撤销降低 AI 写操作风险。
- 支持个人空间和企业空间，满足个人日历和团队协作两类场景。
- 支持可复现演示：本地开发启动和 Docker Compose 一键启动。

### 2.3 非目标

- 第一版不接入第三方日历。
- 第一版不做邮件、短信、微信、飞书、钉钉提醒。
- 第一版不做完整自定义字段系统。
- 第一版不做保存命名视图。
- 第一版不做多语言、多时区、长期记忆和 token 成本统计。

## 3. 目标用户

### 3.1 个人用户

需要快速记录、查看和调整个人日程。关注今天、近期、提醒、冲突和复盘建议。

典型需求：

- “明天上午 10 点提醒我做项目复盘”
- “今天下午有什么安排？”
- “十分钟后再提醒我”
- “撤销刚才的操作”

### 3.2 企业团队成员

参与团队会议和项目排期，需要查看自己相关的企业事件，并通过语音进行快速筛选和操作。

典型需求：

- “安排我和张三明天下午三点做产品评审”
- “显示项目 Alpha 下周所有会议”
- “按负责人分组展示下周评审会议”

### 3.3 企业 Owner/Admin

负责组织成员、企业日历、批量排期和协作数据治理。

典型需求：

- 创建组织并邀请成员加入。
- 管理 Owner/Admin/Member 权限。
- 查看企业操作日志。
- 确认高风险批量操作。

## 4. 产品形态

- 交付形态：Web App 原型。
- 前端：Vue 3 + TypeScript + Vite + Element Plus。
- 后端：Spring Boot + Spring Security + JWT + MyBatis-Plus + Flyway。
- 数据库：MySQL。
- AI：OpenAI 兼容 LLM，Ollama 作为可选本地 LLM。
- 语音识别：OpenAI 兼容 STT，预留多供应商适配器。
- TTS：OpenAI 兼容 TTS 或通用 HTTP TTS，预留多供应商适配器。
- 实时能力：SSE 用于 AI 流式响应，WebSocket 用于站内提醒。

## 5. 核心体验

### 5.1 工作台布局

第一屏直接进入可操作工作台，不做营销页。

```text
顶部：空间切换、模型状态、全局操作
左侧：AI 助手、语音按钮、文本输入、确认卡片、工具调用时间线
中间：月历、表格、甘特视图
右侧：今日焦点、即将到来、站内提醒、最近 AI 操作
```

### 5.2 输入方式

- 语音输入是主入口。
- 键盘输入是兜底入口。
- 两种输入都进入同一个 AI Agent 流程。
- 麦克风权限失败或 STT 失败时提示改用键盘输入。

### 5.3 AI 输出方式

AI 执行结果由三部分组成：

- 自然语言回复。
- 结构化结果卡片。
- 工具调用时间线和可解释摘要。

TTS 语音播报只播报最终回复，不逐条播报工具调用过程。

## 6. 功能范围

### 6.1 注册登录

#### 功能描述

用户可以注册、登录、退出，并保持登录态。所有业务接口从后端认证上下文读取当前用户。

#### 规则

- 密码使用 BCrypt 加密。
- 登录成功签发 JWT。
- 注册后自动创建个人日历空间。
- 前端路由需要登录保护。

#### 验收标准

- 用户可以注册并登录。
- 刷新页面后登录态可恢复。
- 未登录访问工作台会跳转登录页。

### 6.2 个人/企业空间

#### 功能描述

系统支持个人空间和企业空间。事件、提醒、AI 会话、日志都归属某个 `calendar_space`。

#### 规则

- 个人空间自动创建，归属单个用户。
- 创建组织后自动创建企业空间。
- 用户可在个人空间和加入的企业空间之间切换。

#### 验收标准

- 注册后存在个人空间。
- 创建组织后存在企业空间。
- 空间切换后日历数据隔离。

### 6.3 组织与邀请码

#### 功能描述

用户可创建组织，其他用户可通过邀请码加入组织。

#### 规则

- 创建组织者自动成为 Owner。
- 邀请码加入者默认 Member。
- Owner 可任命 Admin。
- Owner/Admin 可管理普通 Member。
- 第一版不做邮件邀请和审批流。

#### 验收标准

- Owner 可创建组织并生成邀请码。
- 新用户可通过邀请码加入组织。
- 成员列表显示角色。

### 6.4 角色权限

#### 权限模型

| 角色 | 权限 |
|---|---|
| Owner | 管理组织、成员、企业日历、操作日志、删除或归档组织 |
| Admin | 创建、修改、删除企业事件，管理企业提醒，查看日志 |
| Member | 查看企业日历，创建/修改/删除自己创建的事件，查看相关提醒 |

#### 规则

- 权限校验必须在后端工具调用层和业务服务层完成。
- 前端隐藏按钮不能作为权限控制依据。
- AI 工具调用必须遵守相同权限模型。

#### 验收标准

- Member 不能删除他人企业事件。
- Admin 可以管理企业事件。
- Owner 可以调整成员角色。

### 6.5 日历事件

#### 功能描述

用户可以创建、查看、搜索、修改、删除日历事件。

#### 字段

- 标题
- 开始时间
- 结束时间
- 地点
- 备注
- 参与人
- 重复规则
- 企业字段：项目、负责人、状态、优先级、标签、类型、自定义字段

#### 规则

- 默认事件时长 60 分钟。
- 默认时区为 `Asia/Shanghai`。
- 数据库存储需要可明确转换时区。
- 删除采用软删除。

#### 验收标准

- 月历、列表、表格、甘特都能展示同一批事件数据。
- 用户可通过表单和 AI 创建事件。
- 搜索和筛选不泄露无权限数据。

### 6.6 事件参与人

#### 功能描述

个人事件默认只有创建者。企业事件支持多个组织成员作为参与人。

#### 规则

- 创建者默认为 organizer。
- 参与人为组织内用户。
- AI 可以从语音识别参与人。
- 匹配多个候选人时必须追问。

#### 验收标准

- 企业事件可选择多个参与人。
- 冲突检测覆盖所有参与人。
- “小王”匹配多人时展示候选列表。

### 6.7 冲突检测

#### 功能描述

系统检测同一用户或企业参与人在同一时间段的重叠事件。

#### 规则

- 前端可即时提示，后端必须最终校验。
- 创建或修改冲突事件时，AI 需要解释冲突原因。
- 用户可确认后强制创建或修改。

#### 验收标准

- 重叠事件被标记为冲突。
- AI 创建冲突事件时返回冲突说明和替代时间建议。

### 6.8 重复事件

#### 功能描述

第一版支持基础重复规则，并预留复杂自然语言重复规则。

#### 支持范围

- 不重复。
- 每天。
- 每周。
- 每月。
- 每年。
- 结束日期。
- 重复次数。
- 自定义规则文本和 JSON。

#### 规则

- 简单规则可直接结构化保存。
- 复杂规则需要 AI 解析并让用户确认。
- 第一版不要求完整覆盖 RRULE。

### 6.9 提醒与站内通知

#### 功能描述

用户可以为事件设置提醒。提醒到达后生成站内通知并通过 WebSocket 推送。

#### 支持选项

- 事件开始时。
- 提前 5 分钟。
- 提前 15 分钟。
- 提前 30 分钟。
- 提前 1 小时。
- 自定义提前时间。

#### 状态

```text
pending
sent
read
snoozed
cancelled
```

#### 验收标准

- 提醒到点后右侧提醒栏出现通知。
- 在线用户通过 WebSocket 收到推送。
- 用户可标记已读。

### 6.10 稍后提醒

#### 功能描述

用户可以通过点击或语音将提醒延后。

#### 固定选项

- 5 分钟后。
- 10 分钟后。
- 30 分钟后。

#### 验收标准

- 点击稍后提醒后，原提醒状态变为 snoozed。
- 到达新时间后再次推送。
- 用户说“十分钟后再提醒我”可触发相同能力。

### 6.11 AI Agent 与 Tool Registry

#### 功能描述

AI Agent 理解用户语音或文本输入，通过受控工具调用层执行日历操作。

#### 工具分类

- Calendar Tools：创建、更新、删除、查询、搜索、冲突检测。
- Reminder Tools：创建、取消、稍后提醒、查询。
- View Tools：视图切换、筛选、分组、排序、高亮。
- Enterprise Tools：成员解析、企业字段更新、批量更新。
- Audit Tools：日志查询、撤销最近 AI 写操作。

#### 规则

- AI 不能直接写 SQL。
- AI 只能通过预定义工具改变系统状态。
- 所有工具调用必须经过权限校验。
- 所有写操作必须记录日志。

### 6.12 工具风险等级

| 等级 | 操作类型 | 执行策略 |
|---|---|---|
| low | 查询、视图切换、单个明确新增 | 可直接执行 |
| medium | 修改单个事件、稍后提醒 | 可直接执行，必须清晰反馈，尽量可撤销 |
| high | 删除、批量修改、修改重复规则、影响多人 | 必须确认 |
| critical | 批量删除、移除成员、修改角色、跨空间操作 | 必须确认并校验高权限 |

#### 验收标准

- 删除事件不会直接执行，而是生成确认卡片。
- 视图切换可直接执行。
- 批量修改必须确认。

### 6.13 多轮对话

#### 功能描述

AI 支持信息缺失追问、参与人消歧、冲突处理、高风险确认和用户中途取消。

#### 示例

```text
用户：帮我安排个会议
AI：你想安排什么主题、什么时间、哪些参与人？
用户：明天下午三点，和产品组，讨论新版排期
AI：产品组包含 5 人，其中 2 人有冲突。要改到四点吗？
```

#### 验收标准

- 信息不完整时不强行创建事件。
- 用户补充信息后可继续同一任务。
- 高风险确认使用持久化 payload 执行。

### 6.14 AI 写操作撤销

#### 功能描述

支持撤销最近一次 AI 执行的写操作。

#### 规则

- 撤销窗口为 10 分钟。
- 只撤销当前用户有权限访问的操作。
- 如果目标数据已被其他操作修改，需要提示无法安全撤销。
- 撤销操作本身也写入日志。

#### 验收标准

- AI 创建事件后 10 分钟内可撤销。
- 超过窗口撤销失败并提示原因。

### 6.15 语音输入

#### 功能描述

前端录音上传到后端，后端转写为文本，再进入 AI Agent。

#### 规则

- 原始音频默认不长期保存。
- 只保存转写文本和识别元数据。
- 文件格式、大小、超时需要校验。

#### 验收标准

- 录音后显示转写文本。
- 转写文本能触发 AI 日历操作。
- STT 失败时可改用键盘输入。

### 6.16 TTS 语音回复

#### 功能描述

AI 最终回复可生成语音播放。

#### 规则

- 个人版默认最终回复后自动播报。
- 企业版默认不自动播报，显示播放按钮。
- TTS 音频临时缓存 30 分钟。
- TTS 失败不影响文字和卡片。

#### 验收标准

- AI 完成后可播放语音回复。
- TTS 服务不可用时文字和卡片正常展示。

### 6.17 企业字段化视图

#### 功能描述

企业空间支持表格、日历、甘特三种视图，围绕同一批事件数据展示。

#### 字段

- 项目。
- 负责人。
- 状态。
- 优先级。
- 标签。
- 类型。
- 备注。
- 自定义字段 JSON 预留。

#### AI 能力

- 切换视图。
- 按项目筛选。
- 按负责人分组。
- 按优先级排序。
- 高亮冲突事件。

#### 验收标准

- “把项目 Alpha 的高优先级会议用表格列出来”可以切换表格并筛选。
- “按负责人分组展示下周评审会议”可以设置分组。

### 6.18 日志与可解释展示

#### 功能描述

前端展示 AI 交互、语音转写、意图识别、工具调用、确认和执行结果。

#### 展示原则

- 展示简洁解释摘要。
- 不展示原始 chain-of-thought。
- 不展示系统 prompt、API Key、供应商内部调试信息。
- 支持展开查看工具调用摘要。

#### 验收标准

- AI 操作后能看到完整时间线。
- 冲突或确认场景能看到原因说明。

## 7. 关键流程

### 7.1 语音创建个人日程

```text
用户点击语音按钮
-> 前端录音
-> 上传音频
-> 后端 STT 转写
-> AI Agent 解析意图
-> Tool Registry 调用 create_event
-> CalendarService 写入事件
-> OperationLog 记录
-> SSE 返回执行进度
-> 前端展示结果卡片
-> TTS 播放最终回复
```

### 7.2 删除事件

```text
用户：删掉明天产品评审
-> AI 搜索候选事件
-> 如果多候选则追问
-> Tool Registry 判定 delete_event 为 high 风险
-> 创建 pending_confirmation
-> 前端展示确认卡片
-> 用户确认
-> 后端使用持久化 payload 删除事件
-> 写入操作日志
```

### 7.3 企业多人会议创建

```text
用户：安排我和张三明天下午三点做产品评审
-> AI 识别企业空间、时间、主题、参与人
-> 参与人唯一匹配
-> check_conflict 检查所有参与人
-> 无冲突则 create_event
-> 有冲突则解释并推荐替代时间
```

### 7.4 稍后提醒

```text
提醒触发
-> WebSocket 推送站内通知
-> 用户点击 10 分钟后提醒
-> 后端将原提醒置为 snoozed
-> 生成新的 trigger_at
-> 到点后再次推送
```

## 8. 非功能需求

### 8.1 安全

- API Key 不暴露到前端。
- AI 工具调用不信任前端传入的 user_id。
- 所有写操作进行权限校验。
- 原始音频默认不长期保存。

### 8.2 可用性

- LLM 不可用时保留手动日历操作。
- STT 不可用时提示使用键盘输入。
- TTS 不可用时不影响文字和卡片。
- 主分支任意时间保持可运行。

### 8.3 可观测性

- 记录 AI 会话、消息、工具调用日志、操作日志。
- 记录 prompt 版本、tool schema 版本、模型供应商和模型名称。
- 不记录第一版 token 和费用统计。

### 8.4 性能

- 月历按月份加载事件。
- 表格视图支持分页。
- 日志支持分页和按会话查询。
- WebSocket 只向目标用户推送提醒。

## 9. MVP 验收标准

1. 评委能通过 README 和 Docker Compose 启动项目。
2. 用户能注册、登录，并进入个人 AI 工作台。
3. 个人版能用语音创建日程、查看日程、触发站内提醒、稍后提醒和 TTS 回复。
4. 企业版能创建组织、邀请码加入、切换企业空间。
5. 企业版能体现 Owner/Admin/Member 权限差异。
6. 企业版能创建多人事件，并做参与人识别或手动选择。
7. 系统能检测基础时间冲突，并让 AI 推荐替代时间。
8. AI 能低风险直接执行，高风险生成确认卡片。
9. AI 写操作能在 10 分钟内撤销。
10. 表格、日历、甘特三种视图可切换。
11. AI 能控制筛选、分组、排序、视图切换和高亮。
12. 工具调用时间线、结构化结果卡片、AI 解释摘要能正常展示。
13. 语音输入失败时可退回键盘输入。
14. TTS 失败时不影响文字和卡片。
15. 主分支任意时间保持可运行。
