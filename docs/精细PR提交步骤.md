# 语音日历 AI Native 精细 PR 提交步骤

## 1. 拆分原则

- 所有新功能都通过 PR 合入主分支。
- 每个 PR 只做一件事，只引入一个可解释、可验证的功能增量。
- 大功能按“数据结构 -> 后端服务 -> API -> 前端接入 -> 验证打磨”的顺序拆分。
- 每个 PR 合并后主分支必须可启动、可构建、核心路径不被破坏。
- 涉及数据库的 PR 必须包含 Flyway migration，不能依赖手动建表。
- 涉及 AI 写操作、权限、确认、撤销的 PR 必须优先补后端测试。
- 前端 PR 至少保证 `npm run build` 通过；后端 PR 至少保证测试或编译通过。

## 2. 推荐分支命名

```text
feature/001-project-bootstrap
feature/002-backend-health
feature/003-frontend-shell
fix/xxx-description
docs/xxx-description
```

## 4. 精细 PR 路线图

### 阶段 A：项目基础与可运行骨架

#### PR 001：初始化前后端与 Docker Compose 项目骨架

- **标题**：初始化 Vue、Spring Boot、MySQL 与 Docker Compose 项目骨架。
- **功能描述**：建立前端、后端、数据库和演示启动目录结构，为后续功能 PR 提供可运行基础。
- **实现思路**：创建 Vue 3 + TypeScript + Vite 前端工程、Spring Boot 后端工程、MySQL Docker Compose、基础 README。
- **测试方式**：运行前端构建、后端编译、Docker Compose 配置校验，确认目录结构完整。

#### PR 002：新增后端健康检查接口

- **标题**：新增后端健康检查接口 `/api/health`。
- **功能描述**：提供评委和前端可探测的后端可用状态。
- **实现思路**：新增 HealthController，返回服务状态、版本、当前时间。
- **测试方式**：启动后端后访问 `/api/health`，确认返回 `UP`。

#### PR 003：接入 Flyway 并创建数据库基线迁移

- **标题**：接入 Flyway 数据库迁移并创建基线表。
- **功能描述**：保证数据库结构可追踪、可复现，为用户和日历表做准备。
- **实现思路**：配置 Flyway，新增 `V1__init_schema.sql`，先创建 `schema_version_note` 或最小基线。
- **测试方式**：启动后端连接 MySQL，确认 Flyway 自动执行并生成记录。

#### PR 004：新增全局后端响应与错误模型

- **标题**：新增统一 API 响应和错误返回格式。
- **功能描述**：让前端可以稳定处理成功、失败、参数错误和权限错误。
- **实现思路**：定义 `ApiResponse`、`ApiError`、全局异常处理器和基础错误码。
- **测试方式**：访问不存在或故意参数错误接口，确认错误格式一致。

#### PR 005：新增前端应用壳与路由骨架

- **标题**：新增前端应用壳、路由和基础布局。
- **功能描述**：提供登录页、工作台页、错误页的前端路由入口。
- **实现思路**：配置 Vue Router、Element Plus、基础 AppShell、路由守卫占位。
- **测试方式**：运行前端，确认页面可访问、路由跳转正常、构建通过。

#### PR 006：新增前端 API 客户端基础封装

- **标题**：新增前端 HTTP 客户端和错误拦截。
- **功能描述**：统一后续所有 API 请求、鉴权头和错误提示。
- **实现思路**：基于 Axios 或 Fetch 封装 `request`，加入 base URL、超时、错误处理。
- **测试方式**：调用 `/api/health`，确认前端能显示后端状态。

### 阶段 B：注册登录与用户上下文

#### PR 007：新增用户表与用户实体

- **标题**：新增用户数据表与后端用户实体。
- **功能描述**：支持注册登录所需的用户身份数据。
- **实现思路**：Flyway 创建 `users` 表，后端新增 Entity、Mapper、Service。
- **测试方式**：执行迁移并运行用户 Mapper 单元测试。

#### PR 008：实现用户注册接口

- **标题**：实现用户注册接口并加密存储密码。
- **功能描述**：用户可以使用用户名、邮箱和密码创建账号。
- **实现思路**：Spring Security BCrypt 加密密码，校验用户名和邮箱唯一。
- **测试方式**：调用注册接口，验证成功、重复用户名、弱密码等场景。

#### PR 009：实现用户登录与 JWT 签发

- **标题**：实现登录接口和 JWT access token。
- **功能描述**：用户登录后获得 token，用于访问受保护接口。
- **实现思路**：校验账号密码，签发 JWT，返回用户基本信息。
- **测试方式**：正确密码登录成功，错误密码返回 401。

#### PR 010：实现后端 JWT 鉴权过滤器

- **标题**：实现 JWT 鉴权过滤器和当前用户上下文。
- **功能描述**：受保护接口能从 token 获取当前登录用户。
- **实现思路**：配置 Spring Security filter，解析 token 并注入认证上下文。
- **测试方式**：无 token 访问受保护接口返回 401，有效 token 可访问。

#### PR 011：实现当前用户信息接口

- **标题**：新增当前用户信息接口 `/api/users/me`。
- **功能描述**：前端刷新页面后可恢复登录态和用户信息。
- **实现思路**：从认证上下文读取当前用户并返回基础资料。
- **测试方式**：携带 token 请求返回当前用户，不携带 token 返回 401。

#### PR 012：实现前端登录注册页面

- **标题**：实现前端登录注册页面和 token 保存。
- **功能描述**：用户可在 Web App 中注册、登录、退出。
- **实现思路**：使用 Element Plus 表单，登录后保存 token，路由跳转工作台。
- **测试方式**：手动完成注册、登录、刷新页面、退出登录流程。

#### PR 013：实现前端路由登录保护

- **标题**：实现前端路由登录保护和登录态恢复。
- **功能描述**：未登录用户不能访问工作台，已登录用户刷新后保持登录。
- **实现思路**：路由守卫调用 `/api/users/me`，失败则跳转登录页。
- **测试方式**：无 token 访问工作台跳登录页，有 token 可进入。

### 阶段 C：个人空间、组织与成员角色

#### PR 014：注册后自动创建个人日历空间

- **标题**：注册后自动创建个人日历空间。
- **功能描述**：每个用户注册完成后拥有默认个人日历空间。
- **实现思路**：新增 `calendar_spaces` 表，注册事务中创建 `personal` 空间。
- **测试方式**：注册用户后查询空间，确认存在且归属正确。

#### PR 015：新增我的日历空间查询接口

- **标题**：新增我的日历空间列表接口。
- **功能描述**：前端可展示个人空间和可访问的企业空间。
- **实现思路**：按当前用户查询 `calendar_spaces` 和组织成员关系。
- **测试方式**：登录后调用接口，确认返回个人空间。

#### PR 016：新增组织表与组织成员表

- **标题**：新增组织和组织成员数据模型。
- **功能描述**：为企业版协作、角色权限和企业空间做数据基础。
- **实现思路**：创建 `organizations`、`organization_members` 表，定义 Owner/Admin/Member 枚举。
- **测试方式**：执行迁移，验证唯一索引和外键约束。

#### PR 017：实现创建组织接口

- **标题**：实现创建组织并自动创建企业空间。
- **功能描述**：用户可创建组织，成为 Owner，并获得企业日历空间。
- **实现思路**：创建组织、成员 Owner 记录、organization 类型 calendar_space。
- **测试方式**：调用接口后检查组织、成员、空间三类记录。

#### PR 018：实现我的组织列表接口

- **标题**：实现我的组织列表和成员角色查询。
- **功能描述**：用户可查看自己加入的组织和角色。
- **实现思路**：基于 `organization_members` 查询组织列表。
- **测试方式**：Owner 创建组织后能在列表看到角色为 Owner。

#### PR 019：实现组织邀请码生成与刷新

- **标题**：实现组织邀请码生成和刷新。
- **功能描述**：Owner/Admin 可以生成或刷新邀请码，用于邀请成员加入。
- **实现思路**：在 `organizations` 保存邀请码哈希或邀请码字段，刷新时重生成。
- **测试方式**：Owner 可刷新邀请码，Member 刷新返回 403。

#### PR 020：实现邀请码加入组织

- **标题**：实现通过邀请码加入组织。
- **功能描述**：用户输入邀请码后加入组织，默认角色为 Member。
- **实现思路**：校验邀请码有效性，写入 `organization_members`，避免重复加入。
- **测试方式**：新用户使用邀请码加入成功，重复加入返回业务错误。

#### PR 021：实现组织成员列表接口

- **标题**：实现组织成员列表接口。
- **功能描述**：企业空间可展示成员，并为参与人选择提供数据。
- **实现思路**：查询组织成员及用户基础信息，按角色排序。
- **测试方式**：Owner/Admin/Member 均可查看所在组织成员。

#### PR 022：实现成员角色调整接口

- **标题**：实现组织成员角色调整。
- **功能描述**：Owner 可以将 Member 调整为 Admin 或恢复为 Member。
- **实现思路**：后端校验操作者角色，禁止非 Owner 调整角色。
- **测试方式**：Owner 调整成功，Admin/Member 调整返回 403。

#### PR 023：实现移除组织成员接口

- **标题**：实现移除组织成员。
- **功能描述**：Owner/Admin 可移除普通 Member，Owner 不可被随意移除。
- **实现思路**：校验角色规则，软删除或标记成员状态。
- **测试方式**：Owner 移除 Member 成功，Member 自行移除他人失败。

### 阶段 D：日历事件核心能力

#### PR 024：新增事件表和事件实体

- **标题**：新增日历事件数据表和后端实体。
- **功能描述**：持久化个人和企业日历事件。
- **实现思路**：创建 `calendar_events` 表，包含标题、时间、空间、企业字段、重复字段。
- **测试方式**：执行迁移，验证关键索引存在。

#### PR 025：实现创建事件接口

- **标题**：实现创建日历事件接口。
- **功能描述**：用户可在个人或企业空间创建事件。
- **实现思路**：校验空间访问权限、时间合法性、默认事件时长和默认提醒策略预留。
- **测试方式**：创建个人事件成功，无权限空间创建失败。

#### PR 026：实现事件详情接口

- **标题**：实现事件详情查询接口。
- **功能描述**：前端可打开事件详情卡片或编辑表单。
- **实现思路**：按事件 ID 查询，并校验当前用户可见性。
- **测试方式**：创建者可查看，非成员不可查看企业受限事件。

#### PR 027：实现事件列表接口

- **标题**：实现按时间范围查询事件列表。
- **功能描述**：月历、列表、甘特可以按时间范围加载事件。
- **实现思路**：支持 `spaceId`、`start`、`end` 参数，按开始时间排序。
- **测试方式**：创建多条事件后按范围查询，确认边界正确。

#### PR 028：实现事件更新接口

- **标题**：实现更新单个日历事件。
- **功能描述**：用户可修改标题、时间、地点、备注和企业字段。
- **实现思路**：后端校验权限、字段合法性、更新时间版本。
- **测试方式**：创建者更新成功，无权限用户更新失败。

#### PR 029：实现事件删除接口

- **标题**：实现软删除单个日历事件。
- **功能描述**：用户可删除有权限的事件，列表中不再展示。
- **实现思路**：使用 `deleted_at` 软删除，保留操作日志预留字段。
- **测试方式**：删除后详情返回不存在或已删除，数据库仍保留记录。

#### PR 030：新增事件参与人表

- **标题**：新增事件参与人数据表。
- **功能描述**：支持企业事件关联多个组织成员。
- **实现思路**：创建 `event_participants` 表，包含 organizer/attendee 和响应状态。
- **测试方式**：执行迁移，验证同一事件参与人唯一约束。

#### PR 031：创建事件时写入参与人

- **标题**：创建事件时支持写入参与人。
- **功能描述**：个人事件默认参与人为创建者，企业事件可选择多个成员。
- **实现思路**：创建事件事务中写入 organizer 和 attendee。
- **测试方式**：创建企业事件后查询参与人列表。

#### PR 032：更新事件参与人

- **标题**：实现事件参与人更新能力。
- **功能描述**：有权限用户可调整企业事件参与人。
- **实现思路**：对参与人差异进行增删，保留 organizer 规则。
- **测试方式**：新增、移除参与人后查询结果正确。

#### PR 033：实现事件搜索接口

- **标题**：实现按关键词搜索事件。
- **功能描述**：AI 和前端可根据标题、备注、项目、标签搜索事件。
- **实现思路**：按空间和权限过滤，使用 LIKE 或全文索引预留。
- **测试方式**：按关键词搜索命中正确，跨空间数据不泄露。

#### PR 034：实现企业字段筛选和排序

- **标题**：实现企业事件字段筛选和排序。
- **功能描述**：企业表格视图可按项目、负责人、状态、优先级、标签筛选。
- **实现思路**：扩展事件列表查询参数，组合 MyBatis-Plus 条件。
- **测试方式**：构造不同字段事件，验证筛选和排序结果。

### 阶段 E：权限、冲突与操作日志基础

#### PR 035：实现空间访问权限服务

- **标题**：实现个人和企业空间访问权限服务。
- **功能描述**：所有业务接口统一判断当前用户是否可访问空间。
- **实现思路**：新增 `PermissionService`，封装个人 owner、组织成员和角色判断。
- **测试方式**：覆盖个人空间、企业 Owner/Admin/Member、非成员访问。

#### PR 036：实现事件写权限规则

- **标题**：实现 Owner/Admin/Member 事件写权限规则。
- **功能描述**：企业成员只能按角色和创建者规则修改事件。
- **实现思路**：封装 `canCreateEvent`、`canUpdateEvent`、`canDeleteEvent`。
- **测试方式**：Member 只能修改自己创建事件，Admin 可修改企业事件。

#### PR 037：新增操作日志表

- **标题**：新增操作日志表并记录手动事件写操作。
- **功能描述**：记录事件创建、修改、删除，为审计和撤销做基础。
- **实现思路**：创建 `operation_logs`，事件写接口写入 before/after snapshot。
- **测试方式**：创建、修改、删除事件后检查日志记录。

#### PR 038：实现基础冲突检测服务

- **标题**：实现单用户和参与人时间冲突检测。
- **功能描述**：创建或修改事件时可识别重叠日程。
- **实现思路**：按参与人、时间区间查询重叠事件，返回冲突列表。
- **测试方式**：构造重叠和非重叠事件，验证检测结果。

#### PR 039：创建事件时返回冲突信息

- **标题**：创建事件时返回基础冲突检测结果。
- **功能描述**：用户创建冲突事件时前端可提示是否继续。
- **实现思路**：默认不强制阻断，返回 `conflicts` 和 `requiresConfirmation` 标识。
- **测试方式**：创建重叠事件，确认响应包含冲突对象。

#### PR 040：更新事件时返回冲突信息

- **标题**：更新事件时间时返回冲突检测结果。
- **功能描述**：拖拽或编辑改期时能识别新时间冲突。
- **实现思路**：排除当前事件本身，复用冲突检测服务。
- **测试方式**：修改到重叠时间返回冲突，修改到空闲时间无冲突。

## 5. 推荐合并门禁

- 后端代码 PR：`mvn test` 或至少 `mvn -q -DskipTests compile` 通过。
- 前端代码 PR：`npm run build` 通过。
- 数据库 PR：本地空库启动成功，Flyway migration 无失败。
- AI/权限/确认/撤销 PR：必须有对应后端测试或明确手动验证步骤。
- UI PR：必须包含至少桌面主视图截图或手动验证说明。
- 演示相关 PR：必须从 README 步骤验证一次。
